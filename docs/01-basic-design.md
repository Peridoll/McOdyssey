# McOdyssey v0.1 基本設計書

文書版: 1.0 / 作成日: 2026-10-01 / 対象: Core・Eco 0.1.0

## 1. 目的と範囲

Minecraftサーバーに、個別に導入できる機能群を提供する。初期版は住民の永続登録、整数通貨MC、プレイヤー間の送金、取引履歴を提供する。Coreを共通基盤として、経済を使わないサーバーが将来CoreとTechだけを選べる構造とする。

店舗、商品の売買、価格変動、税、工場、物流、AI住民、外部DB、Web連携、Tech本体は本版の対象外。既存 `simulator` は独立した実験用プログラムであり、本MODと同期しない。

## 2. システム構成

| 構成要素 | 配置 | 役割 | 依存 |
|---|---|---|---|
| McOdyssey-Core | core | 住民、ワールド単位のDB、非同期実行 | Fabric API、同梱SQLite JDBC |
| McOdyssey-Eco | eco | 口座、送金、取引履歴、コマンド | Core、Fabric API |
| McOdyssey-Tech | 将来 | 技術・設備系機能 | Coreへの依存を想定、未実装 |

依存方向はEco → Core。CoreからEcoへの参照は禁止する。Coreのみの導入で `eco_*` テーブルは作成しない。EcoはCoreをJARへ埋め込まず、別MODとして必要とする。SQLite JDBCはCoreのJARに同梱する。

## 3. 前提環境

Minecraft 1.21.1、Java 21、Fabric Loader 0.16.14以上、Fabric API 0.116.7+1.21.1を基準とする。サーバー専用MODであり、独自クライアントGUIやブロックを追加しない。バニラクライアントからの接続可否は実機試験で別途確認する。

## 4. 機能要件

| ID | 機能 | 仕様・受入条件 |
|---|---|---|
| FR01 | 住民登録 | UUIDを一意キーとし、初回・最終ログイン時刻と最新名を保存する |
| FR02 | 初期所持金 | 初回口座作成時のみ1,000 MC。再ログイン・再起動では再発行しない |
| FR03 | プロフィール | 自分の名前・残高を表示する |
| FR04 | 残高 | 自分の残高を表示する |
| FR05 | 送金 | オンラインの別プレイヤーへ1以上の整数額を送る |
| FR06 | 原子性 | 引落・入金・履歴保存をすべて成功させるか、すべて取り消す |
| FR07 | 履歴 | 自分の送受金を新しい順に最大10件表示する |
| FR08 | 永続化 | DBの正常な停止・再接続後も残高と履歴を保持する |
| FR09 | モジュール分離 | Core単独でEcoの口座・履歴を作成しない |

## 5. 操作仕様

| コマンド | 入力 | 正常時 |
|---|---|---|
| `/mco profile` | なし | 住民名と所持金 |
| `/mco balance` | なし | 所持金 |
| `/mco pay <player> <amount>` | 接続中の1プレイヤー、1以上のlong整数 | 相手名と送金額の成功表示 |
| `/mco history` | なし | 直近10件、なければ「取引履歴はありません」 |

コマンド実行者はプレイヤーを必須とする。OP限定ではない。オフライン送金、管理者通貨発行、送金取消、受取人への通知は実装していない。

## 6. データ・運用設計

DB保存先は `<ワールド>/mcodyssey/core.sqlite`。外部DBサーバーは不要。ワールドごとに財布を分離し、複数サーバーからの共用は想定しない。UUIDをキーとして名前変更でも口座を維持する。履歴の相手名は照会時点の住民名を表示する。

専用の単一DBワーカーで読み書きを順序付け、Tickスレッドで通常のDB I/Oを行わない。起動時の初期化と停止時の待機は例外である。停止時は最大30秒の完了待機後、残りの処理へ割込を要求する。

サーバーを正常停止してワールド全体をバックアップする。起動中はWALを使用するため、DB本体だけをコピーしない。復元は停止中にバックアップのワールドを戻し、起動後に残高・履歴を確認する。

## 7. エラー・制限

自分への送金、0以下、残高不足、受取側long上限超過を拒否する。DBエラーはログへ記録し、利用者には管理者への連絡を案内する。DB障害時のメモリ通貨への切替はない。

金額の範囲は0〜9,223,372,036,854,775,807 MC。初期発行以外の正常な送金は通貨総量を変えない。発行は口座の遅延作成時にも行われる。取引履歴は送金のみで、初期発行の履歴はない。

性能SLA、送金回数制限、監査画面、スキーマ移行、障害復旧自動化、異常終了時のゲーム状態との整合性は未定義。通常停止・DB再接続の確認はクラッシュ耐性の実証ではない。
